# std-cell characterization: timing, power, noise (open-source flow)

An open-source reimplementation of the flow taught in **VSD — Library
Characterization & Modelling** (which uses Paripath **GUNA**): characterize a
standard cell in SPICE across a slew/load matrix, then write a **Liberty
(.lib)** timing/power library with QA checks. Substitute: ngspice for GUNA's
solver, Python for GUNA's measurement/model writer — the methodology is the
same one commercial tools (Liberate, SiliconSmart) automate.

## What is covered (mapped to the VSD Part-1 syllabus)

| Topic | Where | VSD syllabus item |
|---|---|---|
| Delay & transition thresholds (50%, 20/80%) | `decks/tb_delay.sp` | Timing characterization fundamentals |
| Propagation delay tpLH/tpHL, trise/tfall vs slew×load | `scripts/run_char.py` | Propagation delay; output transition |
| Leakage power (input pinned 0/1, DC) | `decks/tb_leak.sp` | Leakage: subthreshold/junction/tunneling |
| Dynamic/switching power (avg supply current @ toggle) | `decks/tb_dyn.sp` | Dynamic, short-circuit, hidden power |
| Crosstalk glitch peak on a victim route | `decks/tb_noise.sp` | Crosstalk glitch; noise on victim |
| Crosstalk delta delay (aggressor quiet vs switching) | `decks/tb_delta.sp` | Crosstalk delta delay, timing impact |
| Liberty modeling: table_lookup, cell_rise/fall, transitions, internal_power | `scripts/run_char.py:write_lib()` | Liberty groups/attributes; NLDM tables |
| QA: monotonicity, positivity checks | `scripts/run_char.py:qa()` | Library QA / sign-off checks |

**Not covered here** (deliberately, listed with how to extend):
- **CCS timing/noise tables** (current-source models): add `.meas` of output
  current waveforms; write `ccsn_*` groups (see syllabus "CCS output current
  models", "CCS noise").
- **Setup/hold/recovery/removal**: requires a sequential cell (DFF). Clone the
  decks, sweep data arrival vs clock edge.
- **Noise immunity curves / Miller capacitance**: add a DC sweep deck measuring
  VTC shift under coupled noise.
- **Variation (Monte Carlo)**: sweep `.param` values across runs (VSD Part 2 /
  GUNA forward models cover this in depth).
- **LEF**: characterization does *not* produce LEF — LEF is a *layout abstract*
  generated by layout tools (`lef write` in Magic) or memory compilers. `lef/inv.lef`
  is a hand-written abstract so the collateral bundle is complete.

## Quickstart

    make char        # runs everything (needs ngspice + python3)
    make report      # QA + noise summary

The bundled transistor models are inline LEVEL=1 cards (educational, 180nm-class,
1.8 V) so the flow runs **without any PDK download**. For PDK-grade numbers,
replace the `.model` cards in `cells/inv.sp` with foundry includes (e.g.
SkyWater `sky130.lib tt`) and resize W/L to the PDK rules.

## Flow diagram

    cells/inv.sp ──► decks/*.sp (ngspice) ──► measurements ──► run_char.py
         (netlist)     (slew×load sweep)        (tp, tr, P, glitch)   │
                                                                       ▼
                                              output/inv_tt_1.8v_25c.lib   (Liberty)
                                              output/noise_report.json     (crosstalk)
                                              output/qa_report.json        (QA)

## Validate the result (downstream consumers)

    # STA with your own library:
    read_liberty output/inv_tt_1.8v_25c.lib   # OpenSTA / yosys both read Liberty

    # Synthesis using your own .lib as target library:
    yosys -p 'read_liberty -lib output/inv_tt_1.8v_25c.lib; ...'
